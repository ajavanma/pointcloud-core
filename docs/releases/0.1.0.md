# PointCloud Core 0.1.0

**Status:** prepared on 2026-10-14; not yet tagged or published to PyPI.

The first release provides NumPy primitives for point-cloud validation,
voxelization, label mapping, and restoring voxel-level results to original
point rows. It is a separate, MIT-licensed library derived from the numerical
operations in PointCloud Workflows.

## Included API

- `PointCloud` and `validate_cloud` normalize aligned arrays, check shapes and
  integer IDs, and keep source-row order without mutating inputs.
- `LabelMap` maps declared class IDs to contiguous indices and restores original
  labels, including an explicit ignore label.
- `voxelize` returns `VoxelizedCloud` with floor-quantized, lexicographically
  sorted voxels, mean features, majority labels, and original-point mappings.
- `lift_voxel_values` reconstructs labels, scores, and other per-voxel values in
  original row order. Excluded rows use a checked fill value rather than
  accidentally indexing a final voxel.
- `PointCloudError` identifies contract violations. Type information is included
  through the package's `py.typed` marker.

NumPy is the only runtime dependency. Python 3.11 or later and NumPy 1.26.4 or
later (below 3) are required; CI tests Python 3.11 and 3.12 against NumPy 1.26.4
and the latest NumPy 2.x. There are no GPU, model framework, dataset format,
CLI, network, or filesystem dependencies in the API.

## Contract and limits

Coordinates and features normalize to float64. Labels, voxel coordinates,
point IDs, and mappings use int64. A shared finite mask excludes invalid
coordinate/feature rows during voxelization; mappings preserve those rows as
`-1`. Label ties choose the smallest numeric nonignored label. Explicit class
order can control ties by encoding labels first.

The implementation holds arrays in memory and requires at least one finite
row. It does not stream large datasets or promise bit-identical floating
reductions across input permutations or NumPy versions. Frozen dataclasses
contain mutable arrays. No PCW artifact or serialized-object compatibility is
introduced by this library. See the [full API contract](../api.md).

Version 0.x is an early API: patch releases preserve documented behavior, while
minor releases may change it with migration notes. After publication, consumers
can constrain the tested series with `pointcloud-core>=0.1,<0.2`.

## Release readiness

The release preparation validates both source and wheel metadata with
`twine check --strict` and runs all numerical tests against the built wheel
outside the checkout under minimum and current NumPy. GitHub's manual
preparation workflow retains tested distribution artifacts without publishing.

Local wheel checks on 2026-10-14 passed all 36 tests and the README example on
Python 3.11.5 with NumPy 1.26.4 and 2.4.6. Both distributions passed strict Twine
metadata checks. The wheel includes the MIT license and typing marker and
declares NumPy as its sole runtime dependency. GitHub CI also checks Python
3.12 before merging the release preparation.

Remaining publication steps are PyPI's pending Trusted Publisher registration,
its verification against repository `ajavanma/pointcloud-core`, workflow
`release.yml`, environment `pypi`, and a final publication decision. No tag,
published GitHub release, or PyPI upload is created by this preparation. An
unpublished GitHub draft can hold the tested preparation distributions for
review. Before publishing that immutable GitHub release, replace its draft
assets with the tested distributions from the final authorized publishing run
and verify their checksums against PyPI. The publishing run rebuilds them, so
preparation artifacts must not be assumed byte-identical.
